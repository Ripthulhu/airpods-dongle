# AirPods Dongle 0.1.65

Conversation Awareness and automatic ear-detection media handling now run in the
dongle. Windows and Linux USB audio do not need NTPods, LibrePods or an extra
driver for these features; the host uses its standard USB audio and media controls.

## Changes

- Conversation Awareness lowers music to one quarter of its current amplitude
  while speech is detected, with a 150 ms fade down and 500 ms restoration. It
  uses the same attenuation for all active speech stages on USB and Bluetooth
  relay input. The host volume slider and AirPods hardware volume remain
  untouched; inactive processing is bit-exact.
- Automatic Ear Detection uses dedicated USB Pause and Play commands on wear
  transitions: removing one of two worn buds or removing the last worn bud can
  pause music. It only resumes within two minutes of its own delivered Pause,
  after the audio stream subsequently became idle. Initial connection cannot
  start playback, and docking a second bud does not pause music when the other
  remains in an ear.
- The saved AirPods Ear Detection and Conversation Awareness switches are
  respected. Known dongle call/microphone paths, a disconnect, ownership changes
  or a USB reset cancel automatic media actions rather than carrying them to
  another session.
- Releases now require version-specific, checked-in notes before publication,
  so the download page explains the actual changes instead of repeating only
  build information.

## Using the controls

Use the same commands from the CLI ZIP, closing other HID control clients first:

```sh
python tools/airpods.py set ear-detection on
python tools/airpods.py set conversation-awareness on
```

Use `off` to disable either feature. Existing pairing, manual reconnect policy,
stem controls and volume synchronization retain their existing behavior.

## Checks and limits

All 75 native sanitizer checks and 187 Python tests passed (one platform skip).
The production audio-pipeline test verifies quarter-amplitude output through Game
Mode transitions, restoration to full amplitude, and no simulated drops or
underflows. The .0076 firmware build passed its codec and runtime-memory gates.

Windows/Linux physical media-player and listening checks have not yet been run
for this release. A host and player must honor standard USB Consumer Play/Pause
commands. Generic USB audio does not expose the exact player or every manual
host action; music activity is inferred from PCM samples, so automatic resumption
is best effort. It does not implement desktop media-session integration or
guarantee every player's behavior. A PC call using the PC's own microphone can
look like ordinary USB audio to the dongle; that host call is not automatically
excluded from attenuation or ear-detection actions.

Firmware installation still needs playback and microphone use paused. This
release does not automatically flash either dongle.

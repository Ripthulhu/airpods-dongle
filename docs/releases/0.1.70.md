# AirPods Dongle 0.1.70

On direct USB playback, the Game Mode switch now asks the .0076 radio to
prioritize the selected AirPods. The radio returns to ordinary scheduling
on Game Mode Off or Bluetooth stream suspend. Background case scanning also
pauses during Game Mode playback. The change supports AAC-ELD on the USB
route and works without a companion app.

Switching modes can briefly raise or lower pitch as the dongle adjusts the
AirPods buffer. The same USB converter keeps its sample history through
the transition. Both modes send one AAC-ELD access unit per packet.
[Playback behavior and measurements](../GAME-TRANSITION.md)

The unified image includes the USB head-tracking preview. A host can request
100 Hz motion or the 30 Hz Game Mode rate. The Linux and Android CLI can
select the controls when the same dongle also exposes the motion interface.
[Motion interface](../USB-CONTROL.md#head-tracking-preview)

The firmware audit fixed handling of delayed Close or Abort messages for
another codec endpoint, failed USB media-key releases, and stale status or
command replies across reconnects. Newly paired AirPods qualify for priority
as soon as their own key is saved. Reopening a stream can recover after the
radio exhausted its attempts to restore ordinary priority on the previous
stream. These cases have regression tests.

In a PC listening check before the audit, automatic priority stayed active
for 306 seconds at 255.2 kb/s with zero stream restarts or controller flushes.
The listener reported clean playback. Weak-signal performance and acoustic
latency were outside that measurement.

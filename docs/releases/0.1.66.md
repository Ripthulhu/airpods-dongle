# AirPods Dongle 0.1.66

Fix the first ear-removal action after connecting, keeping the standalone
Conversation Awareness and ear-detection behavior introduced in
[0.1.65](0.1.65.md).

## Changes

- If the AirPods report that they are worn before model identification or audio
  ownership finishes, use that current connection's cached wear report as the
  initial baseline. The first later removal can then pause music immediately.
- Initializing this baseline never starts or pauses playback, never replays a
  speech event, and cannot reuse another connection's report.
- The audio pipeline, volume synchronization, pairing, reconnect policy and
  Conversation Awareness fades are unchanged.

## Checks and limits

A new sanitizer regression covers early wear reports, first-removal pause,
malformed data and retired connections. Windows listening checks on 0.1.65
confirmed clean playback, Conversation Awareness lowering/restoration and ear
pause/resume with NTPods closed. This follow-up fixes the additional startup
ordering case found during review.

No extra desktop app or driver is required. As before, automatic resume depends
on the host/player honoring standard USB media keys and is best effort: USB audio
does not expose every manual player change or a call using the host's own
microphone. Physical Linux testing remains outstanding.

One image supports both PC and phone Pico 2 W dongles. Pause playback and
microphone use before installing it; flashing preserves saved pairing storage.
